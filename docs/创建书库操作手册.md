# Komga（clouddrive 分叉）创建书库操作手册

面向场景：书库根目录挂在 CloudDrive2 / 115 之类的远程 FUSE 挂载上。
所有结论均来自本仓库源码，文末给出文件与行号。

---

## 0. 先决条件（按顺序确认）

1. **服务已启动，端口 25600**
   `komga/src/main/resources/application.yml:67` → `server.port: 25600`

2. **首次使用必须先 claim 管理员**
   未创建任何账号时，只有 `POST /api/v1/claim` 等少数端点匿名可访问。
   `SecurityConfiguration.kt:84-99` → `/api/v1/claim` 在 `permitAll` 列表内，其余 `/api/**` 一律 `authenticated()`。

   ```bash
   curl -s -X POST http://127.0.0.1:25600/api/v1/claim \
     -H 'Content-Type: application/json' \
     -d '{"email":"admin@example.com","password":"改成你的强密码"}'
   ```

3. **认证方式：HTTP Basic**
   `SecurityConfiguration.kt` 里启用了 `httpBasic`，后续所有请求带 `-u 邮箱:密码`。
   （会话模式下也可先 `POST /api/login` 拿 cookie，但脚本化用 Basic 最省事。）

## 1. 先探路：确认容器内能看到挂载点

`root` 是**容器内视角**的路径，不是宿主机路径。填错会直接 400。

```bash
# 宿主机
ls -la /mnt/115/comic/

# 容器内（替换成你的容器名）
docker exec -it komga ls -la /mnt/115/comic/
```

如果容器内看不到，先修挂载（`--bind` / `--volume` / FUSE `allow_other`），别急着建库。

## 2. 建库请求体全字段

`LibraryCreationDto.kt:5-35`。`name` 和 `root` 是**必填且非空白**（`@NotBlank`），其余都有默认值。

```json
{
  "name": "115漫画",
  "root": "/mnt/115/comic/wnacg",

  "importComicInfoBook": true,
  "importComicInfoSeries": true,
  "importComicInfoCollection": true,
  "importComicInfoReadList": true,
  "importComicInfoSeriesAppendVolume": true,
  "importComicInfoExternalXml": false,
  "importEpubBook": true,
  "importEpubSeries": true,
  "importMylarSeries": true,
  "importLocalArtwork": true,
  "importBarcodeIsbn": true,

  "scanForceModifiedTime": false,
  "scanInterval": "DISABLED",
  "scanOnStartup": false,
  "scanCbx": true,
  "scanPdf": true,
  "scanEpub": true,
  "scanDirectoryExclusions": [],
  "repairExtensions": false,
  "convertToCbz": false,
  "emptyTrashAfterScan": false,

  "seriesCover": "FIRST",
  "hashFiles": false,
  "hashPages": false,
  "hashKoreader": false,
  "analyzeDimensions": true,
  "oneshotsDirectory": null
}
```

### 枚举取值

- `scanInterval`：`DISABLED` / `HOURLY` / `EVERY_6H` / `EVERY_12H` / `DAILY` / `WEEKLY`
  （`ScanIntervalDto.kt`，默认 `EVERY_6H`）
- `seriesCover`：`FIRST` / `FIRST_UNREAD_OR_FIRST` / `FIRST_UNREAD_OR_LAST` / `LAST`
  （`SeriesCoverDto.kt`，默认 `FIRST`）

枚举值传错 → Jackson 反序列化失败 → **400**，不是 500。

## 3. 远程挂载场景的关键字段

### 3.1 `hashFiles`：建议 `false`

默认 `true`。它只控制“是否计算并写入 `book.fileHash`”：

- `TaskEmitter.hashBooksWithoutHash()` 在 `library.hashFiles` 为 false 时**直接不派发任务**（`TaskEmitter.kt:65-71`）
- `BookLifecycle.hashAndPersist()` 进来先查库配置，false 就 return（`BookLifecycle.kt:121-129`）

在这个分叉里，hash 已经改成**纯路径哈希、不读文件内容**（`Hasher.kt:75-84`，注释写明是给 LANraragi 互通用的 SHA-1 relpath），所以开着的 I/O 代价不大。但如果你**不接 LANraragi**，`fileHash` 这列对你没价值，关掉能省掉一轮最低优先级的后台任务。

⚠️ 注意：`fileHash` 和**页级哈希 `BookPage.fileHash`** 是两回事。页哈希由 `hashPages` 控制（默认 `false`），跟 `hashFiles` 无关。

### 3.2 `oneshotsDirectory`：大小写不敏感的子串匹配，慎用

`FileSystemScanner.kt:159`：

```kotlin
if (!oneshotsDir.isNullOrBlank() && dir.pathString.contains(oneshotsDir, true))
```

`contains(..., ignoreCase = true)` —— 是**整条绝对路径的子串匹配**，不是“相对 library root 的目录名相等”。后果：

- 填 `"单话"`，那么 `/mnt/115/comic/wnacg/单话归档/xxx` 也会命中
- 填 `"115"`，整个库全变 oneshot，因为根路径里就有 `115`

**建议**：要么留 `null`，要么填一个足够长、不会误伤的片段。命中后该目录下每个文件各自成为一个 `oneshot = true` 的 Series（`FileSystemScanner.kt:159-169`）。

> **本 fork 的实际情况**：生产开启 `--komga.lrr-path-mode.enabled=true` 时，单行本判定由
> 启动参数 `komga.lrr-path-mode.oneshotDir`（默认 `oneshots`）接管，走的是
> `lrrIsOneshotFile` 的**路径段相等**判断，不是子串匹配。此时建库请求里的
> `oneshotsDirectory` 建议留 `null`，两套机制不要同时用，否则边界情况难以推断。

### 3.3 `analyzeDimensions`：建议 `false`

默认 `true`，会在 ingest 时打开压缩包读图片尺寸。这正是这个分叉的 `thumbnailMode = LAZY` 想避免的“扫描期开归档”行为（`KomgaProperties.kt:32-51`）。

配合 `thumbnailMode=lazy`（默认），扫描可以做到**完全不打开归档**。要尺寸数据可以之后按需触发。

### 3.4 `scanOnStartup` + `scanInterval`

- 远程挂载建议 `scanInterval: "DISABLED"`，改用手动/定时触发，避免 6 小时一次全库 stat 打满 FUSE。
- `scanOnStartup: true` 会让每次重启都全库扫一遍，远程库上通常不值得。

### 3.5 `convertToCbz` / `repairExtensions`

会在扫描期**写回远程目录**。115 上这类写操作容易触发风控或产生重复文件，除非明确需要，保持 `false`。

## 4. 发起创建

```bash
curl -s -X POST http://127.0.0.1:25600/api/v1/libraries \
  -u 'admin@example.com:你的密码' \
  -H 'Content-Type: application/json' \
  -d @library.json | jq .
```

`library.json` 用第 2 节的 JSON 改一下 `name` / `root`。

成功返回 200 + `LibraryDto`。

## 5. 错误码对照

`LibraryController.kt:83-136` 的 catch 分支：

| 状态码 | 触发条件 | 源码 | 处理 |
|---|---|---|---|
| **400** | 根目录不存在 | `LibraryLifecycle.checkLibraryValidity` → `FileNotFoundException`（`LibraryLifecycle.kt:103-104`） | 检查容器内路径、挂载 |
| **400** | 根路径不是目录 | `DirectoryNotFoundException`（`:106-107`） | 同上 |
| **400** | 库名重复 | `DuplicateNameException`（`:109-110`） | 换名字或删旧库 |
| **400** | 路径与已有库**互为父子** | `PathContainedInPath`（`:112-116`） | 见下 |
| **500** | 其他异常 | 兜底分支 | 看日志 |

### 路径嵌套检查的坑

`LibraryLifecycle.kt:113-115` 用的是 `Path.startsWith`，而 `Library.path` 是：

```kotlin
val path: Path by lazy { this.root.toURI().toPath() }
```

`toURI().toPath()` **不会**帮你消除符号链接或 `..`。所以：

- `/mnt/115/comic` 和 `/mnt/115/comic/` —— 尾斜杠在 URI 转换后通常会被归一，但别依赖这个
- 通过 symlink 进到同一个物理目录的两个不同路径，**检查不出来**，会建出两个重叠库，后续扫描互相打架

**建议**：建库前用 `realpath` 统一路径，避免 symlink 别名。

## 6. 建库后的第一次扫描

建库本身**不触发扫描**，需要单独触发。

```bash
LIB_ID=$(curl -s -u 'admin@example.com:密码' \
  http://127.0.0.1:25600/api/v1/libraries | jq -r '.[0].id')

curl -s -X POST -u 'admin@example.com:密码' \
  "http://127.0.0.1:25600/api/v1/libraries/$LIB_ID/scan" -o /dev/null -w '%{http_code}\n'
```

返回 **202** 是正常的（异步任务已入队）。

盯进度：

```bash
curl -s -u 'admin@example.com:密码' \
  'http://127.0.0.1:25600/api/v1/tasks?unfinishedOnly=true' | jq '.[] | {simpleName, group, state}'
```

## 7. 后续改配置

用 `PATCH /api/v1/libraries/{id}`（`LibraryController.kt:160+`）。字段全部可选，**只传要改的**。

```bash
curl -s -X PATCH -u 'admin@example.com:密码' \
  -H 'Content-Type: application/json' \
  -d '{"analyzeDimensions": false, "scanInterval": "DAILY"}' \
  "http://127.0.0.1:25600/api/v1/libraries/$LIB_ID" -o /dev/null -w '%{http_code}\n'
```

两点注意：

1. **`PUT` 已废弃**（`LibraryController.kt:150`，Deprecated since 1.3.0），用 `PATCH`。
2. 改 `root` / `oneshotsDirectory` / `scanCbx` / `scanPdf` / `scanEpub` / `scanForceModifiedTime` / `scanDirectoryExclusions` 中的任意一项，都会让该库下次启动时被**整体重扫**（`LibraryLifecycle.kt:85-95` 的 `isRootFolderModified` 判定）。只改 hash 类或 `analyzeDimensions` 不会触发。

## 8. 可直接粘贴的完整脚本

```bash
#!/usr/bin/env bash
set -euo pipefail

BASE=http://127.0.0.1:25600
AUTH='admin@example.com:你的密码'
LIB_NAME='115漫画'
LIB_ROOT='/mnt/115/comic/wnacg'

body=$(cat <<JSON
{
  "name": "${LIB_NAME}",
  "root": "${LIB_ROOT}",
  "scanInterval": "DISABLED",
  "scanOnStartup": false,
  "hashFiles": false,
  "hashPages": false,
  "hashKoreader": false,
  "analyzeDimensions": false,
  "convertToCbz": false,
  "repairExtensions": false,
  "oneshotsDirectory": null
}
JSON
)

code=$(curl -s -o /tmp/lib.json -w '%{http_code}' \
  -X POST "${BASE}/api/v1/libraries" -u "${AUTH}" \
  -H 'Content-Type: application/json' -d "${body}")

echo "create -> ${code}"
if [ "${code}" != "200" ]; then
  echo "失败，响应："; cat /tmp/lib.json; exit 1
fi

LIB_ID=$(jq -r '.id' /tmp/lib.json)
echo "libraryId = ${LIB_ID}"

code=$(curl -s -o /dev/null -w '%{http_code}' \
  -X POST "${BASE}/api/v1/libraries/${LIB_ID}/scan" -u "${AUTH}")
echo "scan -> ${code} (202 = 已入队)"
```

## 9. 排查清单

| 现象 | 先查 |
|---|---|
| 400 `Library root folder does not exist` | 容器内 `ls` 得到吗？挂载是不是只挂了宿主机没进容器 |
| 400 `Library path ... is a child/parent of existing library` | `GET /api/v1/libraries` 看已有 `root`，是否有重叠；symlink 是否绕过了检查 |
| 400 无反序列化提示 | `scanInterval` / `seriesCover` 枚举拼错 |
| 500 | `docker logs komga \| tail -100`，兜底分支不返回 message |
| 扫描后系列数暴增 | `oneshotsDirectory` 子串误命中，或 `scanDirectoryExclusions` 没配对 |
| 扫描很慢 / FUSE 卡死 | `scanInterval` 没关、`analyzeDimensions` 开着、`scanOnStartup` 开着 |
